# Проверки — обновление 2026-09-19

При длительной браузерной проверке воспроизведено завершение серверного Firefox
с кодом 11. После этого HTTP worker исчезал, gateway терял lease и клиент
переподключался. Успех короткого теста с первыми кадрами не выявлял проблему.

В контейнере был лимит 256 задач (процессов и потоков суммарно). В контрольном
запуске с лимитом 512 Firefox достиг 273 задач без падения. Лимит Firefox
изменён на 512, terminal остаётся на 256; ограничения CPU и памяти сохранены.
Эксперимент с программным рендерингом не устранил сбой и в итоговую версию
не включён. В worker добавлены журналы завершения дочерних процессов и
счётчиков cgroup; gateway/runner логируют ошибки lease.

Отдельно исправлен цикл перехвата одного сеанса двумя вкладками: старая вкладка
получает close 4001 и не пытается автоматически вернуть сеанс. Счётчик сетевых
повторов сбрасывается только после 10 секунд устойчивого соединения.

После исправления три последовательных прогона окончательной версии прошли
успешно (71,20 / 68,41 / 57,03 секунды; всего 196,67 секунды). В каждом
проверены оба приложения: по 20 секунд непрерывного видео без переподключений
после первых кадров, а также корректный перехват одного сеанса. Go-тесты,
vet, сборка и race detector прошли. HTTPS health — 200; сервер отдаёт новый
клиент с обработкой 4001 и ограничением повторов.

Браузерный тест проверяет декодированные кадры, непустые пиксели, рост числа
кадров без смены PeerConnection и отсутствие повторного перехвата после 4001.
Для длительного прогона:

```bash
MVP_BROWSER_KIND=firefox MVP_BROWSER_LAN_IP=192.168.15.38 \
  MVP_BROWSER_HOLD_SECONDS=56 ./testing/browser-check.sh
```

Тесты используют собственные временные профили, БД и namespace `mvp1-browser`.
Автоматические прогоны выполняются на серверной машине через её LAN-IP;
доступ с отдельного клиентского компьютера проверен пользователем.

Ниже сохранён отчёт предыдущего этапа.

## Исправления по результатам интеграции

Docker 29 не публикует порты internal-сети. Для локального стенда runner
подключается к bridge IP контейнера; worker объявляет собственные ICE-адреса.
Рабочая сеть использует публикацию портов и настроенный public IP.

Один ранний тест ввода завершился без контрольного файла, повтор прошёл.
Для устранения вероятной гонки готовности worker теперь ждёт видимое окно
приложения, а не только доступный Xvfb. После этого три повтора успешны.
