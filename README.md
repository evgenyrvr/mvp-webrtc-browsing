# mvp-webrtc-browsing — опубликованные приложения в браузере

Linux-сервер, браузерный клиент на Linux/Windows/macOS. Пилот рассчитан на
двух независимых пользователей и два приложения у каждого. Архитектура:
[C4, уровни 1–4](docs/c4-architecture.md), [решения и требования](docs/architecture.md).

## Текущее состояние

Реализованы Go gateway, SQLite, вход/выход, роли, каталог, администрирование,
атомарные лимиты 2/2/4, Docker/Kubernetes runner и worker с Pion. Браузерный плеер получает
VP8-видео; клавиатура и мышь передаются через DataChannel. Добавлены reconnect,
отзыв управления и очистка сеансов. Протокол описан в [signaling](docs/signaling.md).

Falkon добавлен как основной браузер, Firefox остаётся резервным. Печать передаёт
PDF через DataChannel в локальный браузер. Без запущенного runner запуск приложения
возвращает 503. Развёртывание в реальном Kubernetes требует отдельной приёмки.

Для существующего многоузлового кластера на Ubuntu подготовлены образы, Go backend
для Kubernetes API и генератор ресурсов: [инструкция Kubernetes](deploy/kubernetes/README.md).
Все зависимости приложений входят в worker image; на узлах устанавливать Falkon/Go не нужно.

Docker-тест Firefox/terminal, передачи RTP и ввода прошёл три последовательных
запуска. Подробности и ограничения: [отчёт проверки](testing/verification.md).

Полный порядок сборки и запуска: [инструкция](docs/runbook.md).

## Запуск для проверки из браузера

После сборки образа `./testing/build-worker.sh` замените `SERVER_LAN_IP`
в примере на адрес своего сервера и запустите:

```bash
./testing/lan.sh SERVER_LAN_IP
```

Откройте **https://SERVER_LAN_IP:8443**, подтвердите временный тестовый сертификат.
Логины существующей тестовой БД сохраняются. Для первого запуска пустой БД
задайте bootstrap-переменные, как показано ниже. Реальный адрес сервера храните
в локальной конфигурации, не в репозитории. Подробности и порты — в [runbook](docs/runbook.md).

## Локальный запуск

Go 1.27.1 установлен в `.tools/go`. Скрипт `tools/go.sh` использует эту установку
либо системный Go; зависимости закреплены в `go.mod`/`go.sum`. Все кэши локальны
для проекта. Для первой сборки нужен доступ к Go module proxy.

В Bash из корня проекта:

```bash
export MVP_ADMIN_LOGIN=admin
read -rsp 'Пароль первого администратора: ' MVP_ADMIN_PASSWORD
export MVP_ADMIN_PASSWORD
./testing/run.sh
```

Откройте **http://127.0.0.1:8080**. Используйте точно этот адрес: проверка Origin
не считает `localhost` и `127.0.0.1` одним origin. Остановить сервер — Ctrl+C;
после запуска можно убрать переменную пароля из родительской оболочки:

```bash
unset MVP_ADMIN_PASSWORD
```

Начальная учётная запись создаётся только в пустой БД. Встроенного пароля нет.
При повторном запуске существующей БД переменные bootstrap не требуются.
Пароли хранятся в SQLite как Argon2id-хеши с индивидуальной солью;
ответы API и логи их не содержат. Срок входа — один час без продления активностью.
Старые учётные записи мигрируют автоматически, текущие входы сбрасываются.
БД и кэши исключены из Git.

## Проверка клиентского пути текущего инкремента

1. Войти администратором и открыть «Администрирование».
2. Создать роль, например `browser-users`, и разрешить ей Firefox: запуск,
   управление и печать.
3. Создать пользователя, назначить ему эту роль.
4. В другом профиле браузера войти этим пользователем — в каталоге только Firefox.
5. При запущенном runner открыть Firefox и проверить видео, мышь и клавиатуру.
   Для второго приложения назначить доступ к terminal и открыть его в другой вкладке.
6. Изменить назначения/публикацию у администратора и обновить каталог пользователя.

Редактирование собственного пароля завершает авторизацию и требует нового входа.
Последнего активного администратора нельзя отключить или лишить admin-роли.
Пользователь может иметь несколько ролей; permissions объединяются.

## Проверки

```bash
./testing/check.sh
python3 testing/smoke.py
./testing/rtc-check.sh
# После сборки образа, с доступом к Docker:
./testing/docker-check.sh
```

Скрипт выполняет `go test`, `go vet`, `go build` и `go test -race`, если доступен
C-компилятор. При его отсутствии явно сообщает о пропуске race detector.
Smoke-тест запускает реальный gateway на временном localhost-порту, использует
временную БД и случайный пароль, затем останавливает процесс и удаляет тестовые данные.
Тесты проверяют авторизацию/CSRF, отсутствие паролей в API, объединение ролей,
конкурирующие запуски, лимиты пользователей/приложений, cleanup, независимость
приложений и отзыв доступа. Реальный браузер, видео, ввод, TURN и принтер требуют
отдельных интеграционных проверок. RTC-тест использует два реальных Pion peer,
Docker-тест — серверные приложения и Pion-клиент; это не проверка Chrome.

## Рабочий запуск и следующий этап

[deploy/run.sh](deploy/run.sh) запускает gateway с TLS и отдельной БД;
переменные описаны в [deploy/README.md](deploy/README.md).
Для тестов и рабочего запуска никогда не используются общие volumes или БД.

Виртуальная PDF-печать реализована через [Go IPP](docs/adr/007-go-ipp-printing.md)
и DataChannel. Проверки принудительного relay через coturn по UDP и TCP
описаны в [testing/README.md](testing/README.md). Остаются испытания физического
принтера, внешнего NAT и клиентской матрицы Linux/Windows/macOS.
Одноразовые профили, shell внутри окружения и локальный диалог печати утверждены
в [ADR-005](docs/adr/005-first-pilot-behavior.md). Перед сетевым развёртыванием
нужны адрес TURN и список разрешённых назначений защищённого сегмента.

### Публикации сайтов

Администратор может создать именованную карточку Falkon/Firefox со стартовым URL,
списком доменов/IP/CIDR и TCP-портов и выдать её через роли. Новые публикации
используют отдельные app и WebRTC-worker контейнеры/Pod и Go egress proxy.
Старые общие браузеры сохраняют прежний режим: отзовите их у пользователей,
которым нужен доступ только к опубликованным сайтам.

Настройка и границы защиты: [публикации](docs/publications-design.md),
[ADR-012](docs/adr/012-isolated-site-publications.md),
[Kubernetes](deploy/kubernetes/README.md#публикации-сайтов-с-отдельными-pod).
