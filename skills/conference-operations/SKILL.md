# Запуск и эксплуатация

Изучи текущий способ запуска и целевую инфраструктуру. Для локального MVP
создавай Dockerfile/Compose только для реально используемых компонентов.
Не добавляй Kubernetes или облачные сервисы без требования или обоснования.

## Конфигурация и сборка

- Документируй обязательные настройки, значения по умолчанию и единицы времени.
  Проверяй конфигурацию при старте. В `.env.example` храни только примеры,
  реальные секреты исключай из Git.
- Фиксируй версии инструментов и образов. Для Go используй воспроизводимую
  многоэтапную сборку и непривилегированного пользователя, учитывая CGO и
  системные зависимости выбранных библиотек.
- Разделяй liveness и readiness; готовность должна отражать возможность
  обслужить запрос, включая необходимые зависимости.

## Сеть и остановка

Для браузерного захвата медиа обеспечь secure context: HTTPS в развёртывании,
допустимый localhost при разработке. Прокси должен поддерживать WebSocket upgrade
и таймауты долгих соединений. TLS на HTTP-прокси сам по себе не обеспечивает
доступность UDP-медиа.

Документируй HTTP/WSS, TURN listeners и диапазон relay-портов, а при SFU —
его медиапорты и advertised address. Согласуй firewall и контейнерные публикации
портов с фактической конфигурацией. Проверяй внешний доступ и TURN relay.

При SIGTERM прекрати принимать новые сессии, заверши активные соединения
по установленному дедлайну, останови фоновые задачи и закрой хранилища.
При нескольких экземплярах явно реши маршрутизацию комнат и сигналинга;
балансировщик сам по себе не синхронизирует состояние в памяти.

## Диагностика и результат

Добавляй структурированные логи и метрики активных комнат, участников,
ошибок входа, reconnect и задержек. Не используй room ID и participant ID
как неограниченные labels метрик. Не логируй токены, TURN credentials и полный SDP.

При создании способа запуска опиши команды и сетевые требования в `docs/runbook.md`.
Проверь сборку и запуск доступными средствами. Отдельно сообщи, проверялся ли
реальный внешний звонок. Изменение файлов развёртывания не означает, что сервис
уже опубликован; выполняй внешние действия только в рамках запроса пользователя.
