# ADR-011 — Хеширование паролей и часовой срок входа

Дата: 2026-10-07. Статус: принято пользователем. Отменяет прежнее решение
об открытом хранении паролей в защищённой зоне.

Пароли хранятся в users.password_hash как Argon2id (v19, 19 MiB, 2 прохода,
параллелизм 1, случайная соль 16 байт, результат 32 байта). Профиль соответствует
[рекомендации OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
Используется golang.org/x/crypto/argon2 уже закреплённой версии модуля. Число
одновременных вычислений ограничено двумя. Сравнение constant-time, неизвестный
пользователь также требует вычисления KDF. Проверка не допускает произвольных
параметров стоимости из строки БД. Это не заменяет отдельное ограничение частоты
попыток входа на внешнем периметре.

Миграция schema 3→4 транзакционно хеширует все старые значения, переименовывает
колонку и удаляет старые auth_sessions. Пароль, похожий на хеш, тоже считается
plaintext в старой схеме. Пользователи, роли, grants и пароли для входа сохраняются.
Повторное открытие не хеширует уже сохранённые хеши. Bootstrap и смена пароля
используют тот же алгоритм; пустой пароль при редактировании сохраняет прежний.
Смена пароля отзывает входы; вставка новой сессии повторно проверяет хеш/статус,
чтобы вход со старым паролем не завершился успешно после его изменения.

SQLite использует secure_delete, VACUUM и WAL checkpoint(TRUNCATE) при открытии.
Это очищает рабочие файлы БД, но не удаляет старые внешние копии, snapshots,
файловые журналы и физические остатки SSD. Не создавать новый plaintext-backup
при миграции; старые резервные копии хранить/выводить из эксплуатации отдельно.
После перехода старый бинарник с поддержкой schema ≤3 использовать нельзя.

Срок auth_sessions и cookie — один час. expires_at фиксируется при login,
Identity не продлевает его. Cookie HttpOnly/SameSite=Strict, Secure при HTTPS.
UI получает expires_at/server_time, закрывает медиасоединение и показывает вход.
API проверяет срок на каждом запросе; WebSocket имеет deadline и проверяет
отзыв на heartbeat. Worker получает неизменный срок аутентификации в Offer,
ограничивает им lease, ввод, печать и контекст передачи видео. Новая аутентификация
требует повторного ввода логина и пароля. Уже открытые PDF невозможно отозвать.

Часовой срок входа независим от 30-минутного срока приложения (ADR-010).
Разрыв доступа не продлевает жизнь приложения; действуют существующие cleanup
и таймаут восстановления. Проверки используют управляемое время и принудительное
истечение только в отдельной тестовой БД, без ожидания реального часа.
