# ADR-002: несколько независимых приложений на пользователя

Статус: принято.
Дата: 2026-09-17.

## Контекст

В пилоте одновременно работают максимум два независимых пользователя.
Каждому нужны два активных приложения. В дальнейшем предусматривается
одновременная работа с двумя или тремя приложениями, например Firefox
в одной вкладке и terminal в другой.

## Решение

- Пилот: максимум два активных приложения на пользователя и четыре на стенд.
- Будущее расширение: до трёх приложений на пользователя; при двух пользователях
  потребуется поддержать до шести сеансов после проверки ресурсов и нагрузки.
- Каждый экземпляр приложения имеет собственные `app_session_id`, контейнер,
  worker, PeerConnection, каналы ввода, профиль и print spool.
- Учётная сессия пользователя и сеанс приложения — разные сущности. У одного
  пользователя может быть несколько `app_sessions`; лимита UNIQUE(user_id) нет.
- Каждое приложение открывается в собственной вкладке по адресу вида
  `/sessions/{app_session_id}`. Переключение вкладки не останавливает приложение.
  Потеря фокуса сбрасывает зажатые клавиши только в соответствующем сеансе.
- Каталог показывает активные приложения и позволяет вернуться в их вкладки.
  Повторное подключение к существующему сеансу не создаёт новый экземпляр.
- Для одного сеанса допускается один управляющий PeerConnection. Переподключение
  заменяет его по поколению; другая вкладка не становится вторым контроллером.
- Лимиты пользователей, приложений на пользователя и общего числа сеансов
  задаются отдельно. Для пилота значения — 2 / 2 / 4. Слоты резервируются атомарно,
  включая preparing и reconnecting; ошибка запуска освобождает резерв.
- Остановка приложения и отзыв доступа к нему не закрывают другие разрешённые
  приложения. Logout или отключение пользователя закрывают все его сеансы.
- Ввод и печать маршрутизируются по конкретному сеансу приложения и его владельцу,
  а не только по user ID. SFU в пилоте не требуется.

## Последствия

Контейнеры, кодеры и PeerConnection рассчитываются на четыре одновременных
приложения, а не на два. Производительность проверяется под этой нагрузкой.
Третье приложение пользователя в пилоте отклоняется; включение трёх приложений
в будущем требует изменения лимитов и нагрузочной проверки, но не модели данных.
Разрешение открывать несколько экземпляров одного типа приложения пока не задано;
обязательный сценарий — Firefox и terminal одновременно.

Проверки: независимый ввод и печать в четырёх сеансах, конкурирующие запуски,
reconnect одной вкладки, закрытие одного приложения без влияния на другое.
