# ADR-006: изоляция процессов внутри контейнера приложения

Статус: реализовано; локальный запуск Firefox/terminal в Docker проверен.
Результаты и ограничения: [отчёт](../../testing/verification.md).

Firefox/terminal, Xvfb и оконный менеджер запускаются как UID/GID 1000.
Управляющий Go worker имеет отдельную от приложения идентичность: root **внутри
контейнера**, с удалёнными capabilities кроме SETUID, SETGID и KILL. Они нужны
для запуска и завершения дочерних процессов под UID 1000. Приложение не наследует
управляющие секреты и capabilities. Контейнер не privileged, корневая ФС read-only,
без host mounts и Docker socket, с лимитами процессов, CPU и памяти.

Это уточняет первоначальное предложение об одном непривилегированном UID для
всего контейнера. Одинаковый UID у worker и пользовательской shell позволил бы
прочитать worker token через /proc. Разные UID и очищенное окружение приложения
разделяют права управления и права опубликованного процесса.

Общий секрет coturn никогда не передаётся контейнеру. Runner выдаёт ему только
временные TURN credentials для конкретного сеанса. Worker token относится только
к одному контейнеру; пользовательские процессы не получают его через Env.

Контейнер остаётся границей пилотного доверенного стенда, не эквивалентом VM.
Усиление изоляции до нескольких контейнеров/VM можно рассмотреть отдельно.
Тестовая сеть по умолчанию internal: произвольного выхода к внешним сервисам нет.
Рабочая сеть и разрешённые назначения задаются оператором перед развёртыванием.
