# ADR-004: платформы, клиентский путь MVP и возможный Electron-клиент

Статус: принято; Electron рассматривается как возможное будущее расширение.
Дата: 2026-09-17.

## Контекст

Приоритет MVP — показать полный клиентский путь, возможность и удобство работы
с опубликованными приложениями. Демонстрация должна включать реальное удалённое
приложение и взаимодействие с ним, а не только макет интерфейса или подключение
WebRTC без пользовательского сценария.

## Решение

- Серверная платформа — Linux. Gateway, runner и окружения приложений
  развёртываются на Linux; Windows и macOS как серверные платформы в MVP не входят.
- Клиентские платформы — Linux, Windows и macOS. В MVP пользователь работает
  через Chrome или совместимый браузер без установки отдельного клиента.
- Поддержка платформ — требование к реализации и проверке, а не заявление
  об уже пройденных испытаниях. Версии ОС и браузеров фиксируются в отчёте.
- Приоритет реализации — связный клиентский путь и удобство взаимодействия:
  понятные состояния запуска, обратная связь, управление, переключение приложений
  и восстановление после обрыва.
- В будущем возможно отдельное клиентское приложение на Electron.
  Его реализация, сроки и конкретные нативные функции пока не утверждены.

## Демонстрационный путь MVP

1. Администратор назначает пользователю доступ к опубликованным приложениям.
2. Пользователь входит и видит понятный каталог доступных приложений.
3. Запускает Firefox, видит состояние подготовки, затем изображение приложения.
4. Работает мышью и клавиатурой: вводит текст, прокручивает страницы и использует
   доступный внутренний веб-сервис.
5. Запускает terminal во второй вкладке и переключается между приложениями,
   сохраняя оба сеанса активными.
6. Инициирует печать в Firefox, получает документ локально и проходит
   согласованный сценарий печати; способ локальной печати уточняется отдельно.
7. После краткого обрыва возвращается в своё приложение; видит понятное сообщение,
   если восстановление невозможно.
8. Закрывает одно приложение без остановки другого; выходит из системы,
   завершая все свои сеансы.

Для оценки удобства проверить читаемость текста, соответствие координат мыши,
RU/EN, сочетания клавиш с учётом локальной ОС, отсутствие «залипших» клавиш,
понятность ошибок и задержку реакции на ввод. Численные критерии задержки
устанавливаются после измерений на целевом стенде. Сам по себе успешный
обмен SDP не подтверждает готовность клиентского сценария.

## Подготовка к Electron

Серверные HTTP/WSS-контракты, WebRTC и модель сеансов остаются общими для
браузерного и возможного Electron-клиента. Прикладной UI и обработку протокола
следует отделять от интеграций с локальной ОС. Печать, открытие окон и другие
платформенные действия выделяются по мере реализации в заменяемые адаптеры.

Electron не меняет Linux-платформу сервера, роли и правила доступа. Его появление
само по себе не означает включение автоматической печати, файлового обмена или
других нативных возможностей: они потребуют отдельных решений и проверок.
Упаковку, установку и обновление Electron-клиента рассмотреть при начале этого этапа.

## Последствия

Приёмка MVP включает прохождение клиентского пути на Linux, Windows и macOS.
Если конкретная платформа недоступна для проверки, это явно отмечается;
результаты одной ОС не считаются проверкой остальных. Подготовка к будущему
клиенту и API gateway не должна вытеснять реализацию демонстрационного пути MVP.

Связанные решения: [параллельные приложения](002-concurrent-applications.md),
[будущий API gateway](003-api-gateway-evolution.md).
