# ADR-001: серверный WebRTC endpoint на сеанс приложения

Статус: принято; лимиты приложений уточнены в ADR-002.
Дата: 2026-09-17.

## Контекст

Нужны Firefox/terminal внутри защищённого сегмента, изображение в Chrome,
DataChannel для ввода и печати, максимум два одновременных пользователя.

## Решение

Приняты Go gateway с SQLite, модель ролей, локальный Go runner и Go/Pion worker на
изолированное приложение. Firefox/terminal рисуют в виртуальный X11 display,
FFmpeg кодирует изображение, Pion отправляет его браузеру. Данные ввода и PDF
передаются в рамках того же PeerConnection. coturn обеспечивает relay при NAT.
Пользователи независимы; каждое приложение имеет собственный сеанс.
В пилоте доступны до двух активных приложений на пользователя, до четырёх
сеансов на стенд. Подробности: [ADR-002](002-concurrent-applications.md).

## Рассмотренные варианты

- SFU: полезен для распространения медиа между многими участниками, но не решает
  захват приложения, исполнение ввода и печать. Для независимых сеансов избыточен;
  в пилот не включается.
- VNC/noVNC: готовые механизмы удалённого экрана, но браузерный транспорт обычно
  отличается от требуемой передачи медиа по WebRTC; добавляет ещё один протокол.
- Полностью собственные Go-кодек, X-сервер и печатная система: слишком большой
  объём для MVP. Предлагаются Go-логика и внешние системные зависимости.
- PTY и текстовый браузерный terminal: экономнее видео для терминала, но создаёт
  второй тип представления. Для начала графический terminal использует общий
  видеопайплайн; PTY можно рассмотреть позднее.

## Последствия

Нет межпользовательского медиамикширования и общей комнаты по умолчанию.
На каждый активный сеанс расходуются процессы приложения и видеокодера.
Собственный код пишется на Go, однако браузерный слой требует JavaScript либо
Go/WASM с браузерной обвязкой; Firefox, FFmpeg, Xvfb, CUPS и coturn — внешние программы.
Пользователь подтвердил предложенное окружение. Детали клиентского интерфейса
и печати, ещё требующие уточнения, перечислены в архитектуре.

Проверки реализации: [архитектура](../architecture.md), разделы 3, 4 и 9.
