# ADR-013: приложения в одной вкладке клиента

Статус: принято. Дата: 2026-11-11.

## Решение

По запросу пользователя каталог и опубликованные приложения открываются в одной
вкладке клиентского браузера. В рабочей области доступны переключатели запущенных
сеансов и возврат в каталог для запуска второго приложения. Это уточняет прежний
клиентский сценарий отдельных вкладок, не меняя лимит двух приложений.

Каждый открытый сеанс представлен отдельным same-origin iframe с собственным
WebRTC-клиентом, DataChannel ввода и печати. При переключении iframe скрывается,
но не уничтожается; соединение и heartbeat сохраняются. Ввод скрытого приложения
сбрасывается. При завершении сеанса iframe удаляется, выбирается оставшийся сеанс
либо каталог. Выход из учётной записи удаляет все iframe.

Альтернатива с закрытием соединения скрытого приложения отклонена: существующий
worker завершает отключённое приложение после 90 секунд, а повторное подключение
требовало бы нового ICE-обмена при каждом переключении. Один общий клиент на
несколько видеопотоков потребовал бы переработки жизненного цикла ввода и печати.

## Последствия

- Состояние процессов браузера и терминала сохраняется при переключении и
  переходе в каталог в пределах загруженной страницы.
- Скрытые подключённые приложения продолжают потреблять ресурсы кодирования
  и передачи видео; оптимизация фонового потока отложена.
- Ограничения сеанса 30 минут и авторизации один час сохраняются.
- Встраивание разрешено только для маршрута сеанса с embedded=1 и только
  с того же origin. Остальные страницы сохраняют frame-ancestors 'none'.
- Адрес /sessions/{id} открывает рабочую область; история Back/Forward работает
  внутри текущей вкладки. Перезагрузка страницы заново подключает выбранный сеанс.
