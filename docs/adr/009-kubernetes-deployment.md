# ADR-009 — Запуск в существующем многоузловом Kubernetes

Дата: 2026-10-07. Статус: принято для MVP; требуется приёмка в целевом кластере.

## Контекст

Пользователь выбрал готовый кластер на Ubuntu с несколькими узлами и доступом
к registry. Зависимости приложений должны поставляться внутри образов.

## Решение

Go runner получает backend Kubernetes API наряду с существующим Docker backend.
Каждый запуск приложения создаёт отдельный одноразовый Pod. Worker image содержит
Falkon, резервный Firefox, terminal, Xvfb, Openbox, FFmpeg и шрифты; Go worker
реализует WebRTC, ввод и IPP/PDF-печать. На узлах не нужны эти пакеты или Go.

Gateway и runner работают в одном control Pod с приватным Unix socket,
одной репликой и стратегией Recreate. SQLite хранится на PVC с файловой системой
поверх block CSI. NFS и горизонтальное масштабирование control не входят в MVP.
Пользователи и права сохраняются; активные приложения при рестарте завершаются.

Runner использует projected ServiceAccount token и namespace RBAC для Pods.
У gateway и приложений этого токена нет. Приложения изолированы на уровне Pods,
профилей и временных файлов. Лимиты два пользователя × два приложения сохраняются.

Coturn поставляется отдельным закреплённым образом и работает на выбранном узле
с hostNetwork и стабильным адресом. Для MVP выбран relay-only; TURN должен
маршрутизировать IPv4 Pod CIDR всех узлов. HTTPS публикуется существующим
Ingress/Gateway/LB кластера с поддержкой WebSocket и TLS до gateway.

## Последствия и допущения

Кластер предоставляет CRI, CNI с NetworkPolicy, CSI, registry CA и firewall.
Его версия, StorageClass, ingress-controller и адреса определяются оператором.
Контейнеры не включают ядро Linux или компоненты кластера. Worker API использует
индивидуальный токен через HTTP в доверенной сети кластера; для другой модели
доверия потребуется mTLS или шифрование CNI.

Предварительная загрузка worker image на узлы уменьшает задержку старта.
Падение узла не превращает активный сеанс в мигрируемый рабочий стол. Не использовать
force delete как доказательство остановки приложения при сетевом разделении.

Альтернативы: Docker socket на узлах отклонён для Kubernetes backend; отдельная
БД и несколько control replicas отложены до требования HA. Будущий API gateway
из ADR-003 остаётся отдельным этапом.

## Проверка

Unit-тесты Kubernetes API и генератора дополняются обязательной приёмкой:
server-side dry-run, настоящий запуск на разных узлах, внешний TURN, ввод,
печать, отказ узла, очистка Pods и восстановление SQLite. Docker-тесты эту
приёмку не заменяют. Команды: [инструкция](../../deploy/kubernetes/README.md).
