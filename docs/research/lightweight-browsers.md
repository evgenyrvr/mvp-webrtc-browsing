# Выбор дополнительного серверного браузера

Дата исследования: 2026-10-07. Статус: предложение, не принятое ADR.
Новые браузеры не установлены, сравнительный benchmark ещё не выполнен.
Предположение до уточнения пользователя: нужны современные JavaScript-приложения,
обычный интерфейс с адресной строкой, одноразовый профиль и локальная PDF-печать.

## Кандидаты

| Браузер | Основание для рассмотрения | Ограничение для проекта |
| --- | --- | --- |
| Falkon | KDE позиционирует его как лёгкий браузер; QtWebEngine, основанный на Chromium; готовый пакет Debian 13 | Компактный интерфейс не гарантирует малого расхода RAM движком. Проверить sandbox в нашем контейнере, ввод и Go IPP |
| GNOME Web / Epiphany | Готовый браузер на WebKitGTK; иной движок для сравнительного теста | Совместимость конкретных внутренних приложений, GTK/DBus и печать требуют проверки |
| Chromium | Полноценный современный движок, полезный контрольный вариант | Нет оснований заранее считать его легче Firefox для наших страниц |
| Firefox ESR | Уже работающий вариант с проверенным вводом и IPP | Базовый вариант для сравнения и отдельной настройки первого запуска |
| Dillo | Разработан для быстрого старта и малого расхода ресурсов | Нет JavaScript, ограниченная поддержка HTML/CSS; подходит только для простых страниц |
| NetSurf | Малоресурсный браузер с собственным движком | Согласно документации, JavaScript примитивный и неполный, по умолчанию отключён; не универсальная замена |

Первым кандидатом на экспериментальное опубликованное приложение предлагается
Falkon, вторым — Epiphany. Это приоритет проверки интеграции, а не установленный
рейтинг CPU/RAM. Firefox остаётся базовым вариантом. Пакет Falkon в Debian trixie
на проверенной странице: 25.04.1-1, зависит от Qt 6 WebEngine и Qt PrintSupport.
Версии самого браузера и движка нужно фиксировать отдельно в результатах теста.

## Что показывают имеющиеся измерения mvp1

В [отчёте от 20 сентября](../testing/verification.md) при четырёх активных сеансах:

| Контейнер | RAM | CPU, 100% = одно ядро |
| --- | ---: | ---: |
| Firefox 1 | 548,4 MiB | 38,82% |
| Firefox 2 | 479,1 MiB | 44,11% |
| Terminal 1 | 82,59 MiB | 40,69% |
| Terminal 2 | 88,09 MiB | 40,71% |

Это снимок контейнеров целиком, не память процессов браузера и не средняя нагрузка.
Во всех контейнерах работают Xvfb, Openbox, Go worker и FFmpeg. Близкий CPU
терминалов и Firefox — основание проверить общую видеопередачу отдельно,
но не доказательство того, что всю нагрузку создаёт FFmpeg.
Текущий захват: 1280×720, 20 fps, программное кодирование VP8.

## Как выбрать по измерениям

Сравнить Firefox ESR, Firefox с настроенным первым запуском, Falkon и Epiphany
на одинаковых лимитах контейнера, странице, разрешении, кодеке и FPS.
Не отключать sandbox ради получения лучших цифр.

1. Свежий профиль на каждый запуск. Разделить первый запуск с холодным файловым
   кешем и повторные запуски с прогретым кешем. Не сбрасывать кеш всего работающего
   сервера ради теста. Сделать не менее 10 повторов, сохранить медиану и разброс.
2. Раздельно измерить создание контейнера, готовность страницы, первый
   декодированный кадр и готовность принимать ввод. Наличие окна не доказывает
   готовность страницы.
3. Измерить RAM всего контейнера и PSS дерева процессов браузера. RSS отдельных
   процессов нельзя просто суммировать как физическую память из-за shared pages.
4. Измерить CPU отдельно у браузера, FFmpeg и контейнера: простой, ввод/прокрутка,
   рабочая JavaScript-страница. Наблюдать 30–60 секунд на сценарий.
5. Проверить печать страницы через Go IPP → DataChannel → PDF, RU/EN, Ctrl+L,
   формы, TLS внутренних сайтов и четыре независимых сеанса.
6. Повторить перспективный вариант при 10/15/20 fps; оценить CPU и удобство
   прокрутки. Снижение FPS не обещает пропорционального уменьшения CPU.

Для ускорения Firefox отдельно проверить отключение страниц первого запуска,
проверки браузера по умолчанию и ненужных фоновых функций через штатные политики.
Выигрыш от этого пока не измерен. Прогрев контейнеров может уменьшить ожидание,
но держит RAM занятой: его нельзя считать одновременной оптимизацией всех ресурсов.

сопоставимых результатов CPU/RAM для нашего контейнера. Числа экономии и
название «самого лёгкого современного браузера» без местных измерений не заявляются.
