# Сигналинг и ввод, протокол пилота v1

Браузер открывает `GET /api/v1/sessions/{id}/signal` с WebSocket upgrade.
Gateway проверяет cookie, Origin, владельца сеанса и право запуска.
За первые пять секунд клиент отправляет `{"csrf_token":"…"}` из `/api/v1/me`.
Проверка выполняется до замены действующего соединения.

Gateway отвечает `config` с `generation` и `rtc` (ICE servers, policy).
Chrome создаёт recvonly video transceiver и DataChannels `control` / `pointer`.
После полного сбора ICE он отправляет `{"type":"offer","sdp":{...}}`.
Gateway через приватный runner передаёт offer worker. Ответ —
`{"type":"answer","sdp":{...}}`. В этом инкременте используется **non-trickle ICE**:
все кандидаты находятся внутри SDP; отдельные candidate-сообщения не нужны.
Новый offer создаётся через новое WebSocket-подключение и новое поколение.

Клиент шлёт `ping` каждые две секунды, сервер отвечает `pong`. Gateway регулярно
проверяет авторизацию и права и продлевает восьмисекундный lease worker.
Без lease worker закрывает PeerConnection и сбрасывает зажатые клавиши.
При обрыве сигналинга приложение сохраняется до 60 секунд для reconnect.
Worker без управляющего lease более 90 секунд завершает контейнер;
runner/gateway сверяют состояние и освобождают слот.

Задержанное сообщение не может вернуть отозванные права: SQLite хранит
монотонную версию политики, lease и обновления permissions несут эту версию.
Старая версия не заменяет новую. Старое поколение не отключает новый peer.
Устаревший disconnect не переводит закрытый сеанс обратно в активное состояние.

## Ввод

JSON сообщения имеют `v: 1`; предел одного сообщения — 2048 байт.

| Канал | Сообщения |
| --- | --- |
| `control`, ordered/reliable | `key` (code, down), `button` (button, down, x, y, seq), `wheel` (delta), `reset`, `layout` (code: us/ru) |
| `pointer`, unordered/maxRetransmits=0 | `pointer` (x, y, seq) |

Координаты x/y нормализованы от 0 до 1 по реальному изображению, без полей видео.
Кнопки: 0 левая, 1 средняя, 2 правая. `code` клавиши — физический DOM KeyboardEvent.code.
Колесо ограничено ±3 шагами. Счётчик pointer/button монотонный в пределах клиента.
Старые перемещения после нового клика отбрасываются.

У pointer и control отдельные ограничения частоты. При переполнении control
сбрасываются зажатые клавиши/кнопки, чтобы потерянный keyup не оставлял их зажатыми.
Blur, уход со вкладки и обрыв также сбрасывают ввод. EN/RU меняет раскладку X11;
поддержка сложных IME отдельно не заявлена.

Видео: Xvfb 1280×720 → FFmpeg VP8/20 fps → Pion RTP → браузерный video.
Обработка RTCP включена, ключевой кадр кодируется не реже раза в секунду;
динамическая адаптация bitrate пока не реализована.

Канал `print` и виртуальный PDF-принтер — следующий этап. Текущий worker
не принимает произвольные команды, файлы или неизвестные DataChannels.

## Конкурирующие подключения к одному приложению

Новая вкладка получает управление сеансом; прежняя получает WebSocket close
`4001` и прекращает автоматические повторы. Пользователь может явно нажать
«Переподключить», чтобы вернуть управление. Это предотвращает бесконечный
цикл взаимного перехвата между вкладками или компьютерами. Разные приложения
имеют разные session ID и не вытесняют друг друга.

После сетевых ошибок число автоматических попыток ограничено тремя. Счётчик
сбрасывается только после десяти секунд устойчивого соединения, чтобы короткие
подключения не приводили к бесконечному миганию.

## Канал печати `print`

Клиент создаёт надёжный упорядоченный DataChannel `print`, без ограничений
повторной передачи. Worker принимает один такой канал на соединение.

- JSON `{"v":1,"type":"job-start","id":"32 hex","size":123,"sha256":"64 hex"}`.
- Бинарные сообщения до 16384 байт: 16 байт ID, 4 байта смещения big-endian,
  затем байты PDF. Смещения строго последовательные.
- JSON `{"v":1,"type":"job-end","id":"32 hex"}`.
- Клиент после проверки SHA-256 отвечает `{"v":1,"type":"job-ack","id":"32 hex"}`.
- `{"v":1,"type":"print-revoked"}` удаляет документы из текущего интерфейса.

Один документ передаётся за раз, скорость ограничена 256 KiB/s и размер
буфера отправки — примерно 64 KiB плюс один блок. Проверка права, текущего
соединения, наличия задания в очереди и срока хранения выполняется перед
каждым блоком. После обрыва неподтверждённый документ передаётся заново.
Подтверждение получения PDF не означает печать на физическом устройстве.
