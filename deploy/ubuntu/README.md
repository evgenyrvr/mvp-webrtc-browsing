# Установка пилота на Ubuntu VPS

Скрипт [deploy.sh](deploy.sh) запускается **на целевом сервере от root**.
Он самостоятельный: достаточно скопировать этот файл, клонировать репозиторий
заранее не требуется. По умолчанию собирается проверенный коммит
`6a5b0ddc95d29ce92ca2ed8966250ef15a290bb0`.

Поддерживается Ubuntu 22.04 и новее, amd64/arm64, один VPS с публичным IPv4
на интерфейсе сервера. Для NAT и Kubernetes этот скрипт не предназначен.
Для сборки и загрузки пакетов нужен исходящий доступ к Ubuntu repositories,
GitHub, go.dev, Go module proxy и Docker Hub. Практический ориентир для пилота:
4 vCPU, 8 ГБ RAM и 20 ГБ свободного диска; это рекомендация, не результат
нагрузочного теста данного VPS.

## Первый запуск

Скопируйте файл на сервер любым доступным способом, затем:

```bash
sudo bash deploy.sh install SERVER_PUBLIC_IPV4
```

С доменом, A-запись которого уже указывает на сервер:

```bash
sudo bash deploy.sh install SERVER_PUBLIC_IPV4 app.example.com
```

Адрес приложения: `https://SERVER_PUBLIC_IPV4:8443` либо
`https://app.example.com:8443`. Без предоставленного сертификата создаётся
самоподписанный сертификат: браузер покажет предупреждение, которое необходимо
подтвердить для тестового стенда.

Если есть доверенный сертификат (fullchain) и его ключ:

```bash
sudo env TLS_CERT=/path/to/fullchain.pem TLS_KEY=/path/to/privkey.pem   bash deploy.sh install SERVER_PUBLIC_IPV4 app.example.com
```

При первом успешном запуске скрипт **один раз показывает пароль admin**.
Сохраните его. Не публикуйте вывод установки с этим паролем.
Скрипт удаляет пароль первичного создания из конфигурации после успешного запуска;
в SQLite хранится Argon2id-хеш. Если установка прервалась до завершения, временный
bootstrap-пароль остаётся в root-only `/etc/mvp-webrtc/service.env`, чтобы
повторная установка смогла завершиться. Повторная успешная установка не сбрасывает
пароли пользователей и не заменяет существующий сертификат.

Для установки другой проверенной версии:

```bash
sudo env MVP_REVISION=GIT_COMMIT bash deploy.sh install SERVER_PUBLIC_IPV4
```

Повторная установка собирает новую версию до остановки старой. При переключении
версий активные приложения завершаются. Это не автоматический rollback миграций:
перед обновлением сохраняйте резервную копию данных.

## Порты

Откройте правила **в firewall провайдера** и, если он включён, в firewall Ubuntu:

| Назначение | Порты |
| --- | --- |
| HTTPS / WebSocket | TCP 8443 |
| TURN | TCP и UDP 3478 |
| Прямое WebRTC-медиа | UDP 51000–51003 |
| TURN relay | UDP 52000–52100 |

Существующий доступ SSH сохраните. Скрипт не меняет SSH и правила firewall.
TURN защищён случайным shared secret; relay разрешён только к публичному IP
этого VPS. Клиентская конфигурация использует TURN/UDP. TURN/TLS и проход
через сети, допускающие только TCP 443, этим вариантом не настраиваются.

Обычные приложения Falkon/Firefox имеют исходящий доступ через Docker bridge.
Для ограниченного корпоративного доступа создавайте профили публикаций с
разрешёнными доменами/IP и назначайте права ролям через панель администратора.

## Управление

```bash
sudo bash deploy.sh status
sudo bash deploy.sh logs
sudo bash deploy.sh stop
sudo bash deploy.sh start
sudo bash deploy.sh restart
```

Либо напрямую:

```bash
sudo systemctl status mvp-webrtc-gateway mvp-webrtc-runner mvp-webrtc-turn
sudo systemctl restart mvp-webrtc.target
sudo journalctl -u mvp-webrtc-gateway -u mvp-webrtc-runner -u mvp-webrtc-turn -f
```

Автозапуск включён через `mvp-webrtc.target`.

## Размещение и права

- `mvp-webrtc` — отдельный служебный пользователь без интерактивного входа.
  Его членство в группе `docker` необходимо runner и даёт управление Docker;
  это не отдельный SSH-аккаунт администратора.
- `/opt/mvp-webrtc/release-*/src` — исходники, бинарники и кэш сборки версии.
- `/opt/mvp-webrtc/current` — ссылка на установленную версию.
- `/var/lib/mvp-webrtc/mvp1.db` — рабочая SQLite, пользователи, роли и публикации.
- `/var/lib/mvp-webrtc/runner.sock` — приватный socket runner.
- `/etc/mvp-webrtc/service.env` — root-only конфигурация, включая TURN secret.
- `/etc/mvp-webrtc/tls` — HTTPS-сертификат и закрытый ключ.
- `/etc/mvp-webrtc/turn.conf` — конфигурация coturn.
- `/etc/systemd/system/mvp-webrtc-*.service` — службы.
- Контейнеры сеансов имеют namespace `mvp1-deploy`.

Папки `testing/data` локального стенда не копируются.
Для резервной копии остановите target, сохраните `/var/lib/mvp-webrtc` и
`/etc/mvp-webrtc` с исходными правами, затем снова запустите target.
Не удаляйте старые release-каталоги/образы до проверки новой версии.
Скрипт не занимает чужие каталоги, не переиспользует чужого пользователя и
отказывается от первой установки при уже установленном coturn.

## Проверка после установки

Автоматически проверяются HTTP health и активность трёх служб. Дополнительно
с другого компьютера проверьте вход, запуск Falkon/Firefox/терминала, ввод,
переключение приложений и печать PDF. Успешный health не доказывает
доступность UDP-медиа или TURN. Проверку принудительного relay и работы
четырёх сеансов нужно выполнить отдельно в вашей сети.

Развёртывание проверено на Ubuntu 24.04 (2 CPU, 4 ГБ RAM): Go-компоненты,
Docker-образ и три службы systemd запущены, автозапуск включён. Первый
прогон потребовал продолжения после ошибок DNS и блокировки apt, выбора
доступного зеркала Debian и исправления прав сертификата. Эти исправления
учтены в установщике; повторный полный прогон с нуля пока не выполнялся.

Повторная установка после успешной установки пакетов может использовать
`sudo env MVP_SKIP_PACKAGES=1 bash deploy.sh install PUBLIC_IPV4`.
Этот режим проверяет наличие зависимостей и не обращается к apt; полезен,
если Ubuntu выполняет автоматическое обновление. По умолчанию установщик
ждёт блокировку apt до 300 секунд и откладывает перезапуски сторонних служб.

Если основной CDN Debian медленный, можно указать зеркало, обслуживающее
оба пути `/debian` и `/debian-security`, через `MVP_DEBIAN_MIRROR`.
Например: `sudo env MVP_DEBIAN_MIRROR=ftp.ru.debian.org bash deploy.sh install PUBLIC_IPV4`.
Проверка подписей apt остаётся включённой. По умолчанию используется CDN
из закреплённого базового образа. Лимит CPU браузера — меньшее из 2.5 и
числа процессоров VPS.

Если DNS хоста не подходит для контейнеров, укажите IP доступного резолвера:
`sudo env MVP_DOCKER_DNS=DNS_SERVER_IP bash deploy.sh install SERVER_PUBLIC_IPV4`.
Несколько IP разделяются запятыми. При повторной установке без этой переменной
сохранённое значение не меняется. Настройка относится только к контейнерам MVP;
DNS хоста и других приложений не изменяется. В изолированных публикациях DNS
получает relay/proxy, а app сохраняет запрет прямого сетевого доступа.
